# План подготовки Opros к продаже

## Цель

Подготовить Opros как тиражируемое self-hosted решение для клиник: с безопасной
первичной настройкой, воспроизводимыми проверками, эксплуатационной документацией
и понятной коммерческой моделью. Медицинская логика, форматы ответов и исторические
опросники не меняются без отдельной миграции.

## Архитектурные решения

- Настройки конкретного заказчика остаются вне Git и передаются через `.env`.
- Production запускается только после автоматической preflight-проверки.
- Работоспособность проверяется отдельно на уровне процесса (liveness) и зависимостей
  (readiness).
- Секреты, идентификаторы пациентов, сделок и сессий не выводятся в логи.
- Возможности лицензирования, биллинга и полноценного multi-tenancy не смешиваются
  с текущим hardening и вынесены в коммерческую дорожную карту.

## Этапы

### 1. Аудит и безопасная конфигурация

- Зафиксировать baseline сборки, тестов и dependency audit.
- Добавить полный безопасный шаблон окружения.
- Добавить preflight-проверку обязательных production-настроек.
- Устранить обнаруженное логирование чувствительных идентификаторов.

### 2. Эксплуатационная готовность

- Добавить liveness/readiness endpoints.
- Добавить проверки конфигурации, health endpoints и политики логирования.
- Добавить CI для backend, frontend, secret scan и compose validation.

### 3. Документация продукта

- Подготовить инструкции установки, обновления, backup/restore и rollback.
- Подготовить отчёт аудита с классификацией рисков.
- Подготовить план лицензирования, продажи, внедрения и поддержки.
- Удалять только доказанно неиспользуемые файлы; сомнительные артефакты перечислить
  в отчёте вместо рискованного удаления.

### 4. Проверка и выпуск

- Запустить backend tests, frontend type-check/lint/build и dependency audit.
- Проверить Docker Compose и preflight (если Docker доступен).
- Провести итоговый review по correctness, security, architecture и operations.

## Риски и меры

| Риск | Влияние | Мера |
|---|---|---|
| Локальный Docker недоступен | Нельзя выполнить полный container E2E | Проверить всё доступное локально и явно зафиксировать блокер |
| В логах есть ПДн/идентификаторы | Высокое регуляторное влияние | Allowlist событий, статический regression test |
| Настройки заказчика неполны | Ошибка запуска/небезопасный production | `.env.example` + preflight fail-fast |
| Нет подтверждённого backup restore | Потеря данных | Runbook и обязательная staging-репетиция перед продажей |
| Текущая архитектура single-tenant | Нельзя безопасно продавать как SaaS | Продавать сначала как отдельный инстанс на клинику |
